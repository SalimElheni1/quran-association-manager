# Code review and fix plan (October 2026)

Two review passes over the code: first by concern (security, architecture, duplication), then
screen by screen (renderer page → preload → main-process handler). This file lists what was found
and the order the fixes are made in. Tick a step only when its gate passes.

## Gate for every step

A step is done only when all of these pass, and the next step starts only after that:

1. `npm run lint`
2. `npm test` (Jest: main process + renderer, database mocked)
3. `npm run test:db` (handlers against a real, migrated SQLite database, run under Electron)
4. the Playwright specs (`tests/e2e`) of the screens the step touches; the whole e2e suite at the
   end of each phase (it takes about an hour, so not after every step)

Every fix comes with a test that fails without it. Missing tests found on the way are added.

Baseline before any change (2026-10-30): lint clean; Jest 70 suites / 1,047 tests pass;
`test:db` 111 pass, 4 fail (tests for the `db:rotate-key` channel removed on 2026-10-02 — CI
never runs this suite, so nobody saw it).

## Findings by screen

**Login and first-run setup**
- The forced password change for accounts still on the old default `123456` is only enforced in
  the window; the main-process session gets full roles at once (`authHandlers.js`).
- One lockout for everybody: 5 wrong guesses lock every account for 5 minutes. An unknown
  username returns before bcrypt runs, so the response time tells which usernames exist.
- The login still signs a JWT that nothing uses (sessions live in `sessionManager`), and puts the
  signing secret in `process.env`.

**Dashboard**
- For FinanceManager and SessionSupervisor every visit shows «فشل في تحميل بيانات لوحة التحكم»:
  the page loads the backup reminder (Superadmin/Administrator only) in the same `Promise.all`
  as the statistics, so the refusal throws the statistics away too.
- «تشغيل دليل الإعداد» passes an undefined `token` (left over from the JWT era).

**Students**
- Filtering by memorised surahs or hizbs together with a search, gender, status or fee filter
  returns wrong students: the surah/hizb ids are pushed into the parameter list before the
  WHERE parameters, but their placeholders come after them (in HAVING).
- Filtering by surahs and hizbs at once multiplies the joined rows, so the `SUM(...) = n` checks
  fail and matching students are dropped.
- The list loads every student and paginates in JavaScript.
- `students:getById` returns every column (national id, health conditions, sponsor id card…)
  to every role, including SessionSupervisor, who only needs names for attendance.

**Teachers** — `teachers:getById` also returns every column to every role. An update with no
field builds `UPDATE teachers SET  WHERE…` (SQL error instead of a message); same in classes.

**Classes and enrolment**
- Saving a class's enrolments removes every *inactive* student from the class: they are not
  listed in the dialog, and the save deletes every enrolment that is not in the list.
- The audit user for the charge regeneration comes from the window (`userId` in the payload)
  instead of the session.
- Deactivating an age group used by classes silently turns off the age/gender filter of their
  enrolment dialog (the group is looked up with `is_active = 1`).

**Attendance** — dates are only checked as «string ≤ 40 characters»; a date in another format
breaks the per-day lookups. Several handlers rethrow raw SQLite errors to the window.

**Users**
- `users:update` never validates `roles` (it is taken out of the payload before Joi): `[]`
  removes every role and unknown names are ignored.
- The Excel import of the users sheet is reachable with FinanceManager rights (see Import).

**Finances (income, expenses, student fees, inventory, receipts)**
- The «financial-report» export path (`exportManager.fetchFinancialData` →
  `legacyFinancialHandlers`) reads the pre-2025 tables (`payments`, `donations`, `salaries`,
  `expenses`) and nothing in the window calls it any more.
- `receipt-books:check-exists` checks the same legacy tables; nothing calls it either.
- Fee charges have no unique index; duplicates were repaired by migration 058 and the
  «إعادة ضبط الرسوم» tool.
- `studentFeeHandlers.js` logs with `console.log`, which goes nowhere in the installed app.

**Settings (backup, transfer key, age groups)**
- Restore accepts a plain, unsigned ZIP and runs every statement of it that is not an
  INSERT/REPLACE (DROP, CREATE TRIGGER, ATTACH…).
- Restore deletes the live database before importing, without a transaction; the safety copy is
  only made when a backup folder is set.
- Restore gives the Administrator role to every user without a role.
- Backups don't say which schema they were made with: data migrations never run on the rows of an
  older backup, and columns the app doesn't know are dropped silently.
- Backup keys are stretched with PBKDF2 at 100k iterations (current guidance: 600k).
- The automatic backup first checks one hour after start and never at start; logout closes the
  database, so scheduled backups and fee charges fail until the next login.

**Import / Export (every list screen)**
- `export:generate` (FinanceManager and up): unknown column keys go into the SELECT as they are,
  and keys with `(`, `.` or ` as ` skip the column check — SQL injection (checked: a column key
  `(SELECT value FROM settings WHERE key='association_transfer_key') AS leaked` is run).
- `import:excel` (FinanceManager and up) imports any sheet the window names: users with any role
  including Superadmin, students, teachers, classes, groups. Imported users get a
  `Math.random()` password.
- `import:execute`, `import:generate-template`, `financial:reconcile`, `receipts:generate`,
  `receipts:getStats`, `receipts:validate` are registered but not reachable from the window.

**Profile** — fine; the password checks happen in the main process.

**About** — external links go through the navigation guard; fine.

**Cross-cutting**
- The log file writes every `Error` as `{}` (message and stack are not enumerable): ~160 call
  sites lose their error. Already-stringified objects bypass the redaction.
- Toasts relayed by the main process never show: `require('../index').mainWindow` is undefined.
- `withTransaction` shares one connection between concurrent IPC calls; it is only correct
  while no `await` inside a transaction really waits.
- Migrations: a «duplicate column» error marks the whole file as applied although the rest of it
  was rolled back; foreign keys are not re-checked after migrations.
- The window's role gates (`renderer/utils/permissions.js`) don't match the documented roles or
  the main process: Administrator can't open Finances or Settings, FinanceManager can't open
  Attendance, Teachers or Classes, SessionSupervisor can't open Teachers.
- Electron 32.3.3 has been out of support since early 2025; Electron fuses are not set, so
  `--inspect`, `ELECTRON_RUN_AS_NODE` and `--remote-debugging-port` work on the installed app.
- `isAllowedSender` accepts any `file://` URL that *contains* `dist/renderer/index.html`.
- CI runs lint and the mocked Jest suite only.

**Duplication** — 35 exact clones (1.87%, jscpd). Repeated patterns: the boolean/date → SQLite
conversion loop (8 copies), Joi error → message (14), session → user id (4), user roles query
(5), import sheet-name maps (4), backup decode (2), rules mirrored in main and renderer (age,
password, transfer key, permissions), Income/Expenses pages, FinancialReportsTab.

## Fix plan

### Phase 0 — tests that actually run

- [x] 0.1 Remove the 4 stale `db:rotate-key` tests (keep the `rotateDatabaseKey` ones).
- [x] 0.2 Run `npm run test:db` in CI (release workflow, before the build).

### Phase 1 — security

- [x] 1.1 Export: only known column keys per export type, no pass-through, no expression
      bypass; the IPC schema refuses unknown keys.
- [x] 1.2 Import: each sheet needs the roles of its own write channel (users → `users:add`,
      students → `students:add`, …) taken from `CHANNEL_ROLES`; role names checked; imported
      passwords from `crypto`; remove the unreachable `import:execute` and
      `import:generate-template`.
- [x] 1.3 Restore: a backup that is neither encrypted nor signed (made before 1.3.0) needs the
      user's confirmation after a warning (refusing them would lock out old backups); run only
      `INSERT`/`REPLACE INTO` a known table; keep the current database aside and put it back if
      the import fails; import inside one transaction.
- [x] 1.4 Restore: users of a backup from before `user_roles` (1.0/1.1) get the role their
      `users.role` column held; a user of a recent backup without a role keeps none (instead of
      everyone without a role becoming Administrator).
- [x] 1.5 `users:update`: validate `roles` (known names, at least one).
- [x] 1.6 Forced password change enforced by the main process (the session only allows the
      password change, profile and logout until it is done).
- [x] 1.7 Login: lockout per username; bcrypt also runs for unknown usernames.
- [x] 1.8 `isAllowedSender`: exact path of the app's own page.
- [x] 1.9 Installed app: DevTools off, refuse `--remote-debugging-port`/`--inspect`, Electron
      fuses (RunAsNode, NODE_OPTIONS, inspect off; only load from asar). Checked on a packaged
      Linux build. Asar integrity is left off: electron-builder 24 does not embed the hash it
      needs on Windows (revisit with 1.13).
- [x] 1.10 Backups: new format with a header and 600k PBKDF2 iterations; old backups still open.
- [x] 1.11 Logs: redact strings too; no key hash in the log.
- [x] 1.12 `students:getById`: health, emergency-contact, sponsor and family details only for
      roles that edit students; read-only roles get what the details view shows.
      (`teachers:getById` needs no change: its details view shows every column.)
- [x] 1.13 Upgrade Electron to a supported major: Electron 45.1.0 (from 32.3.3) and
      better-sqlite3-multiple-ciphers 13, whose N-API binaries ship in the package for every
      platform (no native rebuild any more: `postinstall` and `postdist` removed,
      `npmRebuild: false`). Whole e2e suite 132/132 on Electron 45; a packaged build starts,
      opens its database and has its fuses. electron-builder stays at 24.13.3: 26 drops
      `app-builder-bin`, which the release workflow uses to make the installer's `.ico`, and that
      can only be checked on Windows (see "Follow-ups").

### Phase 2 — correctness and architecture

- [x] 2.1 Logger writes errors with their message and stack.
- [x] 2.2 The toast relay is removed instead: nothing listened to it (the window's listener used
      `require('electron')`, which context isolation blocks) and every screen shows the message
      the handler returns.
- [x] 2.3 Logout keeps the database open; the backup scheduler checks at start.
- [x] 2.4 Dashboard loads for every role (backup reminder only for roles that may read it).
- [x] 2.5 Students: correct surah/hizb filters with other filters; SQL pagination.
- [x] 2.6 Enrolment keeps inactive students; audit user from the session.
- [x] 2.7 Empty updates of teachers/classes: not reachable — both schemas require `name`, an
      updatable column, so validation answers first. A db test now pins that behaviour; no code
      change.
- [x] 2.8 Age group deactivation refused while classes use it.
- [x] 2.9 Migrations: a duplicate column no longer hides the rest of the file; foreign keys
      checked after migrating.
- [x] 2.10 Transactions: one at a time, nesting tracked per call chain (AsyncLocalStorage);
      import uses `withTransaction`.
- [x] 2.11 Fee charges: unique index, created when the data allows it (never blocks start-up).
      Cancelled charges count (the generators treat them as there, a restore brings them back);
      generators skip a charge that is already there; a restore drops the indexes while its rows
      come in.
- [x] 2.12 Backups carry their migrations; restore rebuilds the schema of the backup, imports,
      then migrates forward. A backup from a newer version is refused.
      The list is the first line of `backup.sql`, inside what the signature covers. Backups from
      before it are restored as before (today's schema).
- [x] 2.13 Attendance dates validated as `YYYY-MM-DD`; handlers send Arabic messages, not SQL.
      Statuses limited to present/absent/late. The IPC guard turns any SQLite error a handler
      lets through into one Arabic message; the SQL goes to the log.
- [x] 2.14 Remove dead code: JWT, the legacy financial-report export and
      `legacyFinancialHandlers`, the unreachable channels, `receipt-books:check-exists`.
      Also the receipt-service helpers only those channels used, and the unused `getSetting`
      alias. `tests/channelReachability.spec.js` now checks that every registered channel is
      called from the window; it found 38 more channels without a screen (see below).
- [x] 2.15 Window role gates follow the documented roles (decision needed, see below).
      Administrators see Finances and Settings (not the restore section, the Superadmin's); the
      FinanceManager takes attendance and reads teachers and classes; the SessionSupervisor
      reads teachers. Excel export and import buttons only for the roles their channels allow.
- [x] 2.16 Tests that keep `CHANNEL_ROLES`, the handlers' `requireRoles` and the window's gates
      from drifting apart.
      `tests/roleGates.spec.js`. It found the inventory: the window offered the FinanceManager
      buttons (add, edit, delete, in-kind donation, import) that the main process refuses; they
      are now behind `INVENTORY_MANAGE` (see below).
- [x] 2.17 In-kind donations in one transaction (found in 2.16): «إضافة تبرع عيني» made two calls,
      the income then the inventory item; when the second failed, the income stayed without its
      item. Now one channel, `inventory:add-in-kind`, in `withTransaction`. The IPC guard also
      recognises SQLite errors that handlers re-threw as `new Error(err.message)`.

## Follow-ups

- **electron-builder 26.** Needs another way to make `release/.icon-ico/icon.ico` (NSIS wants an
  `.ico`), then a Windows build to check the installer. It is a build tool and does not ship in
  the app. Asar integrity validation (fuse) can be turned on with it.
- **`protocol.registerFileProtocol`** (the `safe-image://` logos) is deprecated since Electron 25;
  move it to `protocol.handle` before Electron removes it.

## Decisions for the maintainer

- **Roles in the window (2.15).** The user manual and `docs/dev/specs/security.md` say an
  Administrator does everything except users, logs and database import, and the main process
  allows that; the window hides Finances and Settings from Administrators. The plan follows the
  documents. If Administrators should stay out of Finances and Settings, the main process and
  the documents change instead.
- **Self-editable profile fields.** A user can change their own employment type, start/end dates
  and notes from the profile. Left as it is.
- **Inventory for the FinanceManager (found in 2.16).** The documents gave the FinanceManager
  the inventory; the main process lets only Superadmin/Administrator change items. The window
  now follows the main process (the FinanceManager reads the inventory) and the documents say
  so. To give the FinanceManager the inventory, set `inventory:*` to `ROLES.FINANCE` in
  `CHANNEL_ROLES` and grant `INVENTORY_MANAGE`; `tests/roleGates.spec.js` checks they move
  together.
- **Channels without a screen (found in 2.14).** 38 channels have a handler and a preload
  method but no screen calls them: groups management (`groups:*` except the list), receipt books
  (`receipt-books:*`), the log viewer (`logs:*`), the financial PDF/Excel report, adding an
  account, the import sheet preview, the per-student and bulk charge tools, and a few lookups.
  They keep their role checks and are listed in `tests/channelReachability.spec.js`
  (`WITHOUT_A_SCREEN`), so a new one cannot appear unnoticed. Kept for now: for each feature,
  either its screen comes or its handlers, preload methods and list entries go.
